# 소품 설정화

결과물은 완성 그림이 아니라 **다른 그림의 레퍼런스**다. 보기 좋은 연출보다 형태와 디테일이 정확하게 읽히는 것을 우선한다.

## 1. 입력 파악
- 요청서(`requests/*.md`)가 있으면 그것을, 없으면 사용자 메시지를 기준으로 한다.
- `props/<소품>.md`가 없으면 생성하지 말고, `props/_template.md`를 바탕으로 설정 파일부터 함께 채우자고 제안한다.
- 스타일은 소품 파일의 `스타일`을 쓰고, 비어 있으면 소유 캐릭터의 기본 스타일을 쓴다.

## 2. 재료 읽기
- `props/<소품>.md` 전체
- `styles/<스타일>.md` 전체
- `refs/props/<소품>/`에 이미지가 있으면 레퍼런스로 함께 넘긴다.

## 3. 프롬프트 조립
아래 순서로 영어 프롬프트를 만든다.

1. **시트 형식**: `prop design sheet, character design reference, multiple views of the same object, plain white background, even flat lighting, no character, no hands holding it`
2. **스타일**: 스타일 파일의 핵심 키워드. 단, 배경·조명 관련 키워드는 1번과 충돌하면 뺀다.
3. **소품 고정 형태**: 소품 파일의 `형태`, `재질과 색`, `문양과 디테일` 전부. 생략하거나 바꾸지 않는다.
4. **뷰 구성**: 소품 파일의 `뷰` 항목. 비어 있으면 `front view, side view, back view`, 디테일 확대 1개
5. **크기 기준**: 소품 파일에 크기가 있으면 `with a simple human silhouette for scale` 등을 선택적으로 추가
6. **네거티브**: 스타일 파일의 금지 요소 + 소품 파일의 `절대 금지` + `background scenery, dramatic lighting, motion blur, text labels`

비율 기본값은 가로로 긴 3:2. 길쭉한 소품(검, 창, 지팡이)은 각 뷰를 가로로 눕혀 세로로 쌓는 배치도 고려한다.

## 4. 생성
- 사용 가능한 이미지 생성 도구로 생성한다.
- 기본 1장. 디자인 탐색 단계(설정이 덜 확정됨)라는 요청이면 2~3개 변형을 생성한다.

## 5. 검수
생성 결과를 직접 보고 확인한다.
- 소품 파일의 `체크리스트`
- **뷰 간 일관성**: 각도마다 문양, 색, 부품 개수, 비율이 같은 물건으로 보이는가
- 배경이 깨끗하고 다른 요소(인물, 손, 텍스트)가 없는가

틀린 항목이 있으면 해당 부분을 프롬프트 앞쪽으로 옮기거나 강조해서 재생성한다. 최대 2회. 그래도 틀리면 멈추고 어떤 항목이 계속 틀리는지 보고한다.

## 6. 저장
`AGENTS.md`의 공통 규칙대로 `outputs/`에 저장한다. `prompt.md`에는 사용한 파일 경로, 최종 프롬프트, 네거티브, 비율, 검수 결과, 재시도 내역을 적는다.

사용자가 결과를 **확정**하면:
1. 확정 이미지를 `refs/props/<소품>/`에 복사한다.
2. 소품 파일의 `상태`를 `확정`으로 바꾸고 레퍼런스 경로를 적는다.
3. 소유 캐릭터 파일의 `소품` 항목에 이 소품이 없으면 추가를 제안한다.
